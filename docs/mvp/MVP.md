# MVP (1차 범위 확정본)

건강 지표(심박/혈압)를 기록하고, 사용자가 설정한 임계값을 기준으로 이상 징후를 감지하여 앱 내 알림으로 알려주는 모바일 앱입니다.

1차 MVP의 목표는 많은 기능을 제공하는 것이 아니라, 아래 핵심 흐름이 실제 배포 환경에서 동작하는 상태를 만드는 것입니다.

```text
회원가입 → 로그인 → 임계값 설정 → 건강 기록 입력 → 임계값 평가 → 알림 확인
```

---

## 1. 1차 MVP 핵심 기능

### 1.1 인증/계정

#### 포함

- 회원가입
- 로그인
- JWT Access Token 발급
- 내 정보 조회
- 프론트엔드 로그아웃
  - 서버 로그아웃 API는 제공하지 않습니다.
  - 클라이언트가 저장 중인 access token을 삭제하고 로그인 화면으로 이동합니다.

#### 제외

- Refresh Token
- Refresh Token Rotation
- 서버 로그아웃 API
- 회원 탈퇴
- 탈퇴 계정 상태 관리
- 토큰 블랙리스트

#### 정책

- 1차 MVP에서는 access token만 사용합니다.
- access token은 짧은 만료 시간을 사용합니다(30분).
- 토큰 만료 시 사용자는 다시 로그인합니다.
- 사용자가 로그아웃 버튼을 누를 경우 프론트에서 access token을 삭제합니다.

---

### 1.2 건강 데이터 입력/조회

#### 포함

- 심박수(HR) 기록 입력
- 혈압(BP) 기록 입력
- 측정 시각(`measuredAt`) 저장
- 내 건강 기록 목록 조회
- 건강 기록 단건 상세 조회
  - 입력값
  - 평가 결과
  - 위반 내역

#### 제외

- 건강 기록 수정
- 건강 기록 삭제
- 생성 후 10분 수정 제한 정책
- 기록 수정 시 alert/violation 재평가
- 고급 기간 필터
- 그래프
- CSV 내보내기

#### 정책

- 건강 기록은 1차 MVP에서 “생성 후 조회하는 사실 데이터”로 취급합니다.
- 잘못 입력한 기록을 수정/삭제하는 기능은 2차 기능으로 미룹니다.
- 목록 조회는 최신순 정렬을 기본으로 합니다.
- 1차 MVP에서는 기간/타입 필터와 페이지네이션을 제공하지 않습니다.
  - 기록 수가 많아지는 경우 2차에서 pagination을 추가합니다.

---

### 1.3 사용자 임계값 설정

#### 포함

- 사용자별 임계값 조회
- metric 단위 임계값 설정
  - 기존 threshold가 없으면 생성합니다.
  - 기존 threshold가 있으면 같은 metric의 값을 업데이트합니다.
- 지원 지표
  - 심박수: `HR`
  - 수축기 혈압: `BP_SYS`
  - 이완기 혈압: `BP_DIA`
- 지원 규칙
  - 범위 기반 규칙만 지원
  - `minValue`, `maxValue` 기준

#### 제외

- threshold id 기반 상세 조회
- `ruleType` 확장 구조
- `threshold_range` 별도 테이블
- threshold 버전 관리
- threshold soft-delete
- threshold 삭제 기능
- 여러 rule type 지원

#### 정책

- 사용자 1명은 metric 하나에 대해 threshold를 최대 1개만 가질 수 있습니다.
- API는 `metric` 기준 upsert 방식으로 동작합니다.
  - 예: `PUT /thresholds/HR`
- threshold 수정은 기존 row를 새 버전으로 복사하지 않고, 현재 row를 단순 업데이트합니다.
- 과거 기록의 평가 결과는 이미 저장된 violation snapshot을 기준으로 유지합니다.

---

### 1.4 규칙 기반 평가

#### 포함

- 건강 기록 생성 시 현재 사용자의 threshold 기준으로 즉시 평가
- 측정값이 threshold 범위를 벗어나면 violation 생성
- violation이 1개 이상이면 alert 1개 생성
- 건강 기록 상세에서 violation 조회

#### 제외

- 재평가 버튼
- threshold 변경 시 과거 기록 자동 재평가
- 연속성 평가
  - 예: 24시간 내 3회 중 2회 초과
- 쿨다운
  - 예: 동일 유형 알림 30분 내 중복 방지
- 복합 조건 평가
- AI/추천 기반 평가

#### 정책

- 1차 MVP 평가는 “기록 생성 시점의 현재 threshold”만 기준으로 합니다.
- 설정된 threshold가 없는 metric은 평가하지 않습니다.
  - 예: `BP_SYS` threshold만 있고 `BP_DIA` threshold가 없으면 수축기만 평가합니다.
- 혈압 기록(`BP`)은 수축기와 이완기를 각각 `BP_SYS`, `BP_DIA` metric으로 분리하여 평가합니다.
- violation에는 평가 당시의 threshold 값을 snapshot으로 저장합니다.
- threshold가 나중에 수정되어도 과거 violation은 자동 변경하지 않습니다.

---

### 1.5 알림

#### 포함

- 건강 기록 생성 시 위반 사항이 있으면 앱 내 알림 생성
- 알림 목록 조회
- 알림 읽음 처리
- 알림 목록의 `healthRecordId`를 이용한 건강 기록 상세 이동

#### 제외

- 알림 단건 상세 조회
- 푸시 알림
- `is_silent` 정책
- 과거 입력 데이터의 silent alert 처리
- 알림 삭제
- 알림 고급 필터
- 알림 페이지네이션 고도화

#### 정책

- 1개의 건강 기록에서 violation이 1개 이상 발생하면 alert는 1개만 생성합니다.
- alert 메시지는 사용자에게 바로 보여줄 수 있는 요약 문구로 저장합니다.
- alert 상세 정보가 필요하면 alert의 `healthRecordId`로 건강 기록 상세 API를 조회합니다.
- 1차 MVP에서는 모든 alert를 일반 앱 내 알림으로 취급합니다.

## 3. 1차 MVP 완료 기준

### 백엔드

- 회원가입 API가 동작한다.
- 로그인 API가 access token을 발급한다.
- access token으로 내 정보 조회가 가능하다.
- threshold 목록 조회가 가능하다.
- metric 단위 threshold 설정/upsert가 가능하다.
- 건강 기록 생성/목록/상세 조회가 가능하다.
- 건강 기록 생성 시 설정된 threshold 기준으로 평가가 수행된다.
- 위반 발생 시 violation과 alert가 생성된다.
- alert 목록 조회와 읽음 처리가 가능하다.

### 프론트엔드

- 사용자가 회원가입/로그인할 수 있다.
- 사용자가 임계값을 설정할 수 있다.
- 사용자가 심박/혈압 기록을 입력할 수 있다.
- 사용자가 자신의 건강 기록 목록과 상세를 볼 수 있다.
- 사용자가 생성된 알림을 확인하고 읽음 처리할 수 있다.
- 사용자가 알림에서 연결된 건강 기록 상세로 이동할 수 있다.

### 배포/문서

- 백엔드 API가 배포 환경에서 접근 가능하다.
- 프론트엔드가 배포 환경에서 접근 가능하다.
- README에 실행 방법, 주요 기능, API 문서 링크가 정리되어 있다.
- API 문서가 실제 구현과 일치한다.
- 이력서/면접에서 설명할 수 있는 핵심 흐름이 정리되어 있다.
